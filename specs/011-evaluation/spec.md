# Feature Specification: Evaluation Harness

**Feature Branch**: `011-evaluation`

**Created**: 2026-09-13

**Status**: Draft

**Input**: Add a keyless evaluation harness: a gold set of scenarios replayed with
a scripted LLM over the real tools, asserting deterministic outcomes (tool
sequence, final state, rendered component) and exiting non-zero on failure; wire
it into the local gate (P7, TT-2).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Deterministic evals over the real harness (Priority: P1)

A scenario scripts the model's turns and runs them through the real loop, tools,
and stores, then asserts only deterministic outcomes: the tool sequence, the cart
state, and the rendered components. Model prose is never asserted.

**Why this priority**: P7 (evals are first-class) and TT-2 (keyless replay). The
harness's behaviour must be testable without a provider.

**Independent Test**: Run the harness; every scenario passes with no API key.

**Acceptance Scenarios**:

1. **Given** the gold set, **When** the harness runs, **Then** each scenario's
   tool sequence and rendered components match the expectation.
2. **Given** an ungrounded add, **When** it runs, **Then** the cart is unchanged
   (the error is deterministic).

---

### User Story 2 - Evals gate the build (Priority: P1)

The harness runs in the local gate and fails the build on regression.

**Independent Test**: Break a scenario; the gate exits non-zero.

**Acceptance Scenarios**:

1. **Given** a passing suite, **When** `scripts/ci.sh` runs, **Then** the eval
   step passes.
2. **Given** a regression, **When** the harness runs, **Then** it exits non-zero
   and prints the failing scenario.

### Edge Cases

- No API key or network: the harness still runs (scripted LLM only).
- A scenario that scripts too few turns: the mock repeats the last turn; the
  expectation still holds or the scenario is reported as failed.
- A new tool or component: scenarios are extended; the runner needs no change.

## Requirements *(mandatory)*

- **FR-001**: A scenario MUST declare the user text, the scripted turns, the
  expected tool sequence, and the expected rendered components.
- **FR-002**: The runner MUST use the real loop, tool registry, and stores (only
  the LLM is scripted).
- **FR-003**: The runner MUST assert deterministic outcomes only (tool sequence,
  cart, components) and MUST NOT assert model prose (TT-2).
- **FR-004**: The runner MUST exit non-zero if any scenario fails and print which.
- **FR-005**: The harness MUST be keyless (no provider, no network) (P8).
- **FR-006**: The harness MUST run in the local gate (`scripts/ci.sh`) (P7).
- **FR-007**: The gold set MUST cover search, add-to-cart, checkout render, and a
  merchant proposal (staged, unchanged).

### Key Entities

- **Scenario**: `name`, `user_text`, `turns`, `expect_tools`, `expect_components`,
  `expect_cart`.
- **EvalResult**: `name`, `ok`, `failures`.

## UI Requirements

No browser surface. Evals are a backend/CI artifact; the report is printed to the
terminal. (WV-5 permits backend-only features with a recorded reason.)

## Observability

The harness prints a per-scenario report; it can emit spans through the same
`Tracer` if desired, but the report is the observable artifact.

## Success Criteria *(mandatory)*

- **SC-001**: All gold scenarios pass keyless.
- **SC-002**: A regression makes the harness exit non-zero.
- **SC-003**: The harness runs as part of `scripts/ci.sh`.
- **SC-004**: No assertion depends on model prose.

## Assumptions

- `MockLLMClient` (scripted turns) is the replay engine.
- The gold set is small and grows with features.
- Evals are not exposed in the browser.

## Measured Results

- Gold scenarios: **12/12** pass keylessly in the gate (the set grew from 5 at
  this feature to 12).
- Source: `evals/run.py` (regenerated by `make ci-fast`); aggregate:
  [`specs/RESULTS.md`](../RESULTS.md).

## Real-World Coverage

- **Input distribution**: gold scenarios (scripted); the set grows with features.
- **Data quality**: only the model is scripted; the loop, tools, and stores are
  real, so assertions cover deterministic outcomes.
- **Edge & failure modes**: a failing scenario is reported and the gate exits
  non-zero.
- **Scale envelope**: 12 scenarios; the system envelope is measured in `docs/scale.md`.
- **Degradation**: fully keyless; no provider needed.
- **Change evidence**: gold scenarios 12/12 (`specs/RESULTS.md`).
