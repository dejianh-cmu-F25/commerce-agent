# Agent Note: Skills load on demand, not into the prompt

Status: implemented (2026-09-13) — feature `019-skills`

## Problem

The architecture reserves skills (`skills/<name>/SKILL.md`) as the mechanism for
long-tail procedures, but none existed. Adding them raised two questions:

1. **How do skills reach the model?** Dumping every skill body into the system
   prompt is simple but violates context discipline (HR-6) as skills grow.
2. **How does the model choose?** A classifier would be another moving part; the
   model already chooses tools.

## Alternatives considered

- **Inline every skill body in the system prompt.** Simplest, but the prompt
  grows without bound and the model must wade through unrelated procedures.
  Rejected (HR-6).
- **A separate intent classifier to pre-select a skill.** More control, but a new
  model step, cost, and nondeterminism. Rejected.
- **Make skills callable code.** Too heavy; skills are prose procedures.
- **Store skills in the database.** No need; files are the natural authoring
  surface and make "add a skill" a one-file change (HR-11).

## Decision

- **Catalog + on-demand body (progressive disclosure).** The system prompt lists
  each skill's name and description; `use_skill(name)` returns the full body as a
  tool result. This keeps the prompt small and makes skill use observable.
- **Files with optional frontmatter.** `skills/<name>/SKILL.md`, optionally
  prefixed with `---\nname: …\ndescription: …\n---`; without it, the directory
  name and first line are used. Adding a skill needs no code (HR-11, PB-4).
- **Fail-soft.** A missing or disabled skills directory yields an empty library
  and no `use_skill` tool; malformed files are skipped (P8, RD-1).
- **Model-driven selection.** The catalog is the guide; no separate classifier.

## Consequences

- The prompt grows with the number of skills (names + descriptions), not their
  bodies; very large catalogs would need selection, which is a future concern.
- Skill use is visible in the trace and the chat as a `use_skill` tool step.
- `use_skill` bodies are static text, not tool results from the storefront, so
  they carry no prices/stock/policy claims (P4 stays intact).
- Two example skills ship (`trip-planning`, `size-and-fit`); they are demo
  procedures, not an exhaustive library.
