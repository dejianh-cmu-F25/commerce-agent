# Agent Note: Local CI gate replaces GitHub Actions

Status: implemented (2026-09-13)

## Problem

This is a solo project, and the GitHub Actions workflow added latency to every
push and pull request (three jobs, including a Docker image build) for checks
that already run in seconds on the developer's machine. The feedback loop was
slower than the work it guarded, and the required status checks blocked merges
whenever a run was queued or slow.

## Decision

Delete `.github/workflows/ci.yml` and make the gate **local**:

- `scripts/ci.sh` runs the whole gate on the machine: `ruff check` + `ruff format
  --check`, `pyright`, `pytest tests/unit tests/integration`, `spec_review.py`,
  `verify_notes.py`, and the frontend `lint`/`typecheck`/`test`/`build`. Flags:
  `--fast` (skip `npm ci`) and `--with-image` (also build the Docker image).
- `Makefile` targets: `ci`, `ci-fast`, `ci-image`, `setup-hooks`.
- `.githooks/pre-push` runs `scripts/ci.sh --fast`; enable once with
  `git config core.hooksPath .githooks` (or `make setup-hooks`). It can be
  bypassed with `git push --no-verify`.
- Constitution: GH-4 now defines the local gate; TT-3 says pyright runs in the
  local gate; Governance drops "status checks required". The PR template points
  at `scripts/ci.sh`.
- Branch protection: the required status checks were removed (they would never
  report again). PR-required, linear history, and no force-push/delete remain.

## Alternatives considered

- **Keep GitHub Actions as-is.** Rejected: it is the latency being removed.
- **Keep the workflow but run it only manually (`workflow_dispatch`).** Rejected
  for now as unnecessary; the local gate covers the same checks. It can be added
  back trivially if a clean-machine run is ever wanted.
- **Keep it on `main` pushes only.** Rejected: a post-merge check still spends
  minutes of CI and reports after the fact.
- **Trim the workflow (drop the Docker job, add concurrency).** Rejected: still
  network-bound and slower than local for a single developer.
- **A `pre-commit` framework.** Rejected: an extra dependency for what one hook
  and a shell script already do (P6, HR-9).

## Consequences

- PRs no longer wait on GitHub; the developer runs `make ci` (or the pre-push
  hook) before pushing. The PR template records the result.
- There is no automated safety net on the remote. The gate must be run locally;
  CI is a convention enforced by the checklist, not by the platform.
- `docker build` is opt-in locally (`--with-image`) and no longer runs on every
  change.
- Branch protection no longer has required status checks; the other protections
  (PR required, linear history, no force push/delete) are unchanged.
- If the project later gains collaborators or a release process, a manual or
  main-only GitHub workflow can be reintroduced.
