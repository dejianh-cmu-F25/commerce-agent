# Agent Note: The scale envelope and SLOs are declared and measured

Status: implemented (2026-09-13) — feature `029-scale-slo`

## Problem

The project had numbers for *correctness* (gold scenarios, retrieval hit-rate,
ablation) but none for *operability*. There was no statement of how much data or
concurrency the system must survive, no latency or error budget, and no way to
see a regression. SC-1 and SC-3 were open: "it works small" was the only claim.

## Alternatives considered

- **Measure the real model's latency.** Dominated by provider latency, costs
  money, and is noisy. Rejected as the envelope metric; the real eval already
  reports per-run latency.
- **Tight latency budgets.** Would flake on a loaded CI host and block PRs for
  noise. Rejected.
- **Measure the keyless stack with generous regression guards.** Chosen: free,
  deterministic, and catches the regressions that matter (an accidental network
  call, a blocking sleep, an O(n²) loop).

## Decision

- **`docs/scale.md`** declares the dimensions (catalog, knowledge chunks,
  concurrency, ops, session length, cost) and the SLO budgets (retrieval p95 ≤
  2000 µs, turn p95 ≤ 10000 µs at concurrency 16, error rate 0, cost ¥10).
- **`evals/scale.py`** measures TF-IDF retrieval and a full scripted agent turn
  at concurrency 1/4/16/64, reporting p50, p95, throughput, and errors; it writes
  the envelope to the report and **fails the gate** when a budget is breached at
  the target concurrency.
- **`scripts/check_results.py`** validates the section/row presence but not the
  exact timings — wall-clock numbers are not reproducible run to run.

## Consequences

- A latency regression now fails the gate instead of going unnoticed, and the
  envelope is a falsifiable claim (dimensions + measured behavior).
- The budgets are ~1000× the measured values; they catch order-of-magnitude
  regressions, not small drifts. A tighter signal (baseline-relative) is future
  work.
- **Residual gaps**: no multi-tenant isolation test, no long-session memory test,
  no large-corpus (>10⁴ chunks) retrieval test — documented in `docs/scale.md`.
